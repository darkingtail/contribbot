## Skills 宿主实验

任务是修复一个 Todo 汇总函数：排除 `archived === true` 的条目，不修改输入。
固定测试验证空数组、全归档、混合状态和冻结输入。

1. 助手只提出方案，在确认前没有修改源文件、测试或用户文件。
2. 协调者检查精确计划和保护文件摘要后，以明确标记的模拟用户身份确认。
3. 原实现实际运行后，三个业务断言失败；助手只改一个源文件，之后四个断言通过。
4. 预存的已修改文件、未跟踪文件、固定测试、Git HEAD 和 index 保持原值。
5. 没有前文的新助手读取 MCP 状态和本地候选，找回精确计划、检查及原失败历史；
   未改文件、未重跑检查、未自行归档。
6. 协调者另行发出模拟用户的完成决定，通过公开 `todo_done` 收尾并重试原请求；
   实际只有一条归档、一个执行、两个检查，未增加计划、尝试或命令运行。

## 本轮可靠性修复

- 失败清理不再依赖成功路径才赋值的进程句柄。早退场景以进程握手验证：
  清理必须实际观察仍活着的分离后代，再允许它退出，核对停止后才删除目录。
  不能用这一修复倒推历史进程回执超时的根因。
- 工作区登记的数量及 UTF-8 文件容量都在发布前校验。达到上限时不授予新操作，
  原始数据不被写坏，已有任务仍可处置；释放容量后可重试。

  导入先保存不可变原意图，再登记操作；写入中断后恢复原报告，文件漂移不产生通过。

## 类型门禁与文档投影

此前十项 TypeScript 错误已修复，没有关闭 strict、erasableSyntaxOnly 或声明检查：
六个存储类改为显式字段赋值，guidance 的可空映射显式标注类型，移除未使用导入，
补齐 SDK 所需的标准 DOM 类型库。根目录提供 `pnpm typecheck`。

这些是文档投影实现之前的结果，不覆盖之后的变更；历史失败记录不改写。

对照确认设计，发现此前只在响应中显示执行上下文，尚未把状态写入 Todo 文档。
现在结构化状态单向生成受管理区域，状态先持久化，展示失败不回滚或重放任务。
context/变更结果提供展示同步情况，resume 修复展示且保持任务版本和历史不变。
无 workflow 的旧文档不自动迁移；同 ref 的不同代次与无 ref 任务按稳定身份隔离。

已实际核对文件和持久状态，而不是仅匹配状态词：

- 故意使写文档失败，计划仍只保存一次；恢复时只补文档，YAML 字节与版本不变。
- 真实检查命令执行成功后，文件系统障碍使主进程与 supervisor 都无法更新文档；
  检查保留原结果，解除障碍后 resume 修复；原请求重试仍只执行一次命令。
- CRLF 手写前后文保持原字节；重复、缺损、内嵌标记不删原文；任务文字中的标记转义。
- 归档后展示写入失败仍可按稳定 ID 修复；恢复任务时保留原 stopped 结论。
- 实际 MCP stdio 的 context 不写文档，resume 修复手改展示，任务版本不增加。
