## 当前约定

| 概念 | 约定 | 备注 |
| --- | --- | --- |
| Todo 状态 | `idea / backlog / active / paused / done / cancelled` | 不再接受 Todo 的 `pr_submitted / not_planned` |
| 普通更新 | `todo_update` 只写 `idea / backlog / active` | PR、分支和笔记仍是独立元数据 |
| 未开工或非受管取消 | `todo_cancel` | 明确决定、精确 Todo ID 与生命周期版本；不创建虚假的执行或验收 |
| 受管取消 | `todo_control` 后安全本地 `stopped` 收尾 | 必须有匹配的取消决定；未处理操作不得跳过 |
| PR 进度 | 独立的关联和远端观察 | 提交或合并 PR 本身不改变 Todo 状态 |
| 上游追踪状态 | 保留上游领域自己的 `pr_submitted` | 不与 Todo 生命周期混用 |
| 归档 | `todo_archive` 预览后选择精确快照 | 完成、取消均不自动归档 |
| 旧 Todo 状态数据 | 明确报不支持，不转换、不改写 | 不提供兼容读取或迁移工具 |

## 取消入口

先读取 `todo_context`。使用 `todo.id` 和 `todo.lifecycle_revision`；
未设置生命周期版本时值为 `0`。

```json
{
  "repo": "owner/repo",
  "todo_id": "t-<exact-stable-id>",
  "expected_lifecycle_revision": 0,
  "decision": "用户明确要求取消该任务的决定或对话定位"
}
```

以上为 `todo_cancel` 参数。取消后保留 `last_cancellation`，包括决定、
时间和当时的生命周期版本。尚未执行的任务仍没有 execution；普通已有执行
记录为 `abandoned`，不删除已有代码或证据，也不假装验收通过。

相同版本和决定的重试不产生新取消。重开或恢复后的版本变化会拒绝旧取消请求，
要求读取当前状态并取得新的决定。`last_cancellation` 只是上一次取消事实，
不代表重新打开后的当前状态，也不是内容验收证据。

受管执行继续走现有停止控制和安全收尾，不能通过普通取消绕过。
PR/claim 的未结算操作、保留的 Issue 关闭日志、未完成的归档或恢复均阻止普通取消。
Issue 与 Todo 的状态和权限仍然独立。

## 普通 Issue 调用被停止

普通 Todo 的 `issue_close` 已开始，等待 GitHub 返回时才收到暂停或取消，
会进入停止控制，但不能提前记为 `paused/cancelled`。原日志也会阻止继续、
本地收尾和工作区迁移。受管 Issue 收尾只能处理身份完全一致的自身日志，
不能借此跳过其他操作。

原调用仍在运行时，在每次远端写入前保存派发记录，返回后保存实际结果；
确认所有已派发请求均返回并落盘后，在 Todo 锁内先保存不可变核对记录，
再删除活动日志。没有派发写入的情况也记录原始请求和停止决定。
此时只表示原调用已处置，**不自动安顿暂停、取消、完成或归档**。
关闭请求已返回时保留实际关闭事实，不重开 Issue。

核对记录写入成功、日志删除失败时，相同请求可利用完整日志摘要与原始字节
完成清理；不会重发评论或关闭。评论、生命周期、原始日志或停止历史不匹配时
拒绝重试。恢复继续后也不自动重发旧关闭请求，另一次关闭需要新的明确决定。
请求失败或返回结果未保存时保留待处理；当前 Issue 状态、超时或评论标记
都不能证明原请求已经结束。

只读 GET 失败与写请求结果未知分开：已结束的失败 GET 只记录方法和时间，
不保存原始错误文本，不冒充 Issue 状态观察。仍为普通执行时，精确重试也能
在核对磁盘日志后承担当前调用的结果处置。若 GET 先失败、用户随后才暂停，
原格式日志明确记录零次写入派发，精确重试可保存“零派发恢复”依据并清理；
不补造之前的读取结果、不发新请求。存在写入派发但缺少原结果核对记录时，
不能套用这条例外。已有有效核对记录与原日志不一致时仍拒绝。

## Windows 进程查询

首轮进程失败已原样单线程复测，4 项中仍有 2 项失败。实际测量表明本机
Windows PowerShell 每次查询约 2 秒，导致多次身份查询累积后超过测试进程
自己的退出时间。PowerShell 7 的相同查询约 0.3 秒。

Windows 现在优先尝试已有 `pwsh.exe`，仅找不到程序时回退 `powershell.exe`；
两次尝试共用 3 秒总预算，不安装软件、不改 PATH、不缓存进程身份。
时间格式显式固定为 invariant round-trip。超时、权限错误、非零退出和
无法解析的时间仍为未知，不能因此释放任务。其他平台仍使用 `ps`。

Claude round-140 支持可选优先使用 PowerShell 7。采纳总预算、固定格式和
不缓存要求；未采纳扩大失败回退范围的建议，避免把查询错误当作程序不存在。
新增 16 项隔离测试中 12 项先失败，修改后 16 项全部通过；
4 项真实进程身份测试和原先失败的 4 项恢复测试均通过。
没有延长测试超时或放宽断言。仅有 Windows 5.1 的主机仍有较高查询成本；
回退路径的模拟测试不等于该环境的完整时序验收。
