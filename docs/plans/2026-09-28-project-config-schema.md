## 2. 全字段示例

该示例管理自己的 fork，明确选择关注示例 parent 和另一个仓库。
归档时间以注释展示，因为 `active` 状态不能同时带 `archived_at`。

```yaml
# 配置结构版本，不是 contribbot 软件版本，也不是并发修改版本。
schema_version: 2

# 管理主体。Todo、Knowledge、Consult 等项目记录归这个仓库。
# 完整 owner/repo；不是分支、URL 或本地目录。
repository: darkingtail/antdv-next

# contribbot 项目生命周期，不是 GitHub 仓库或 Todo 状态。
lifecycle:
  status: active
  # archived 状态才必填；active 状态不能出现：
  # archived_at: "2026-09-28T12:00:00+08:00"

# 主体直接 fork 自哪个仓库，是事实快照，不是追踪选择。
parent:
  status: confirmed
  repository: antdv-next/antdv-next
  # 上一次成功核实此关系的时间，不是全局更新时间或同步时间。
  observed_at: "2026-09-28T10:00:00+08:00"

# 向管理主体贡献时，可选的默认代码来源仓库。
# 本例主体已经是自己的 fork，无需再绑定它自己。
contribution:
  working_fork: null

# 用户明确选择持续关注的来源，不因存在 parent 而自动加入。
tracking:
  status: configured
  sources:
    - repository: antdv-next/antdv-next
    - repository: ant-design/ant-design
```

## 3. 全部字段

本候选仅有六个一级键。完整存储文件均显式写出；禁止未知键，
不能把新增内容悄悄放进任意分组。新字段需要明确的契约与版本策略，
不能承诺旧解析器会接受。

| 字段路径 | 类型或取值 | 必填条件 | 备注 |
| --- | --- | --- | --- |
| `schema_version` | 整数，固定 `2` | 始终 | 未知版本拒绝，不自动转换 |
| `repository` | `RepositoryRef` | 始终 | 管理主体，普通配置更新不改变身份 |
| `lifecycle` | 对象 | 始终 | 项目生命周期分组 |
| `lifecycle.status` | `active` / `archived` | 始终 | 不与 Todo、GitHub 仓库状态联动 |
| `lifecycle.archived_at` | `Timestamp` | 仅 `archived`，且必填 | `active` 时禁止出现 |
| `parent` | 对象 | 始终 | 直接来源的关系快照 |
| `parent.status` | `unknown` / `none` / `confirmed` | 始终 | 观察结果，不是用户愿不愿意绑定 |
| `parent.repository` | `RepositoryRef` | 仅 `confirmed`，且必填 | `unknown` / `none` 时禁止出现；不能等于主体 |
| `parent.observed_at` | `Timestamp` | `none` / `confirmed` 时必填 | `unknown` 时禁止出现 |
| `contribution` | 对象 | 始终 | 此处规定键存在，不强制用户选择工作 fork |
| `contribution.working_fork` | `RepositoryRef` 或 YAML `null` | 始终 | 无绑定用 `null`；非空时不能等于主体 |
| `tracking` | 对象 | 始终 | 用户持续追踪意图 |
| `tracking.status` | `pending` / `none` / `configured` | 始终 | 未决定不等于明确不追踪 |
| `tracking.sources` | 来源对象数组，至少一项 | 仅 `configured`，且必填 | `pending` / `none` 时禁止出现，不用空数组代替 |
| `tracking.sources[].repository` | `RepositoryRef` | 每个来源必填 | 当前来源对象仅此字段；不能重复或等于主体 |

`RepositoryRef` 是 GitHub.com 的 `owner/repo` 字符串，不接受空字符串、
URL、SSH 地址、本地路径、功能分支或额外路径段；比较和去重采用统一的
大小写规范化规则。格式合法不证明仓库存在、关系成立或拥有操作权限。
当前不增加主机字段，不把多平台地址塞进这个字符串。

`Timestamp` 是带时区的日期时间字符串，采用 ISO 8601 写法，例如
`"2026-09-28T10:00:00+08:00"` 或相应 UTC 时间；在 YAML 中使用引号。
格式通过不能证明观察真实发生；正式值必须来自对应操作，不能复制示例时间。

禁止出现的字段必须省略，不能写 `null` 占位。
`working_fork` 明确允许 `null`，但字符串 `"null"` 不是空值。
发现缺字段应报告具体路径，不在普通读取时自动补齐文件。

## 4. 生命周期的全部状态

| 状态 | 合法字段 | 禁止字段 | 备注 |
| --- | --- | --- | --- |
| `active` | `status` | `archived_at` | 项目正在使用 |
| `archived` | `status`、`archived_at` | 其他未定义字段 | 用户明确归档后的项目状态 |

```yaml
lifecycle:
  status: active
```

```yaml
lifecycle:
  status: archived
  archived_at: "2026-09-28T12:00:00+08:00"
```

归档是 contribbot 本地项目生命周期，不是删除项目，不会归档 GitHub 仓库、
改变 Todo 状态或替代运行中操作的停止流程。
归档项目排除默认活动列表和巡检；`init` 不自动恢复它。
用户明确维护其配置不等于恢复项目或获得新的执行授权。

## 5. Parent 的全部状态

| 状态 | 合法字段 | 禁止字段 | 备注 |
| --- | --- | --- | --- |
| `unknown` | 仅 `status` | `repository`、`observed_at` | 从未成功查明，不是“不是 fork” |
| `none` | `status`、`observed_at` | `repository` | 成功查询确认不是 fork；不是用户选择不追踪 |
| `confirmed` | `status`、`repository`、`observed_at` | 其他未定义字段 | 成功查明直接 parent，来源不得等于主体 |

```yaml
parent:
  status: unknown
```

```yaml
parent:
  status: none
  observed_at: "2026-09-28T10:00:00+08:00"
```

```yaml
parent:
  status: confirmed
  repository: antdv-next/antdv-next
  observed_at: "2026-09-28T10:00:00+08:00"
```

`observed_at` 只描述这一组关系的最近一次成功核实时间，不是整份配置、
全仓库扫描、代码同步或 PR 的时间，也不设一个隐含有效期。
查询失败不会把旧 `confirmed`/`none` 改成 `unknown`，不会更新成功时间、
擦除已有来源或伪造“没有 parent”；当前查询失败另行说明。

只有明确的初始化或刷新操作保存新事实，普通查看不写文件。
执行依赖该关系的同步等操作时仍核实当前事实，旧快照不提供写入许可；
本次实时核实一致，不因旧时间较早就强迫用户再手动刷新。
关系未知或查询失败不阻止无关的本地 Todo 工作。

## 6. Contribution 的全部取值

| `working_fork` 的值 | 意义 | 约束 | 备注 |
| --- | --- | --- | --- |
| `null` | 没有默认绑定 | 仍显式保存该键 | 可以是尚未绑定，也可以是有意不绑定；不等于没有 fork |
| `owner/repo` | 向管理主体贡献时的默认代码来源仓库 | 与主体不同；绑定时核实 fork 网络关系 | 不要求是主体的直接子 fork；具体操作仍核实端点与权限 |

```yaml
contribution:
  working_fork: null
```

以下是另一份项目配置的局部示意：管理贡献目标，代码来自自己的 fork。
这不是把上一份配置的主体自动改掉，也不是创建或迁移项目的请求。

```yaml
repository: antdv-next/antdv-next
contribution:
  working_fork: darkingtail/antdv-next
```

`working_fork` 不是功能分支、本地工作区、parent 或贡献目标。
当管理 `darkingtail/antdv-next` 本身时，不把它再填成自己的工作 fork；
无默认绑定也可以在自己的分支开发，或在具体 PR 操作显式指定 head/base。

本地项目归属、PR 的代码来源和 PR 的目标分别确定。
向 parent 发 PR 不会搬移 Todo、Knowledge 或 Consult，也不要求另建 parent 项目。
修改默认绑定不改写已有交付计划和历史 PR，不自动完成或归档 Todo。

## 7. Tracking 的全部状态

| 状态 | 合法字段 | 禁止字段 | 备注 |
| --- | --- | --- | --- |
| `pending` | 仅 `status` | `sources` | 尚未取得明确选择，取消问答或不回答仍是待定 |
| `none` | 仅 `status` | `sources` | 用户明确当前不持续追踪来源 |
| `configured` | `status`、非空 `sources` | 其他未定义字段 | 每项仅包含一个 `repository`，允许用户选中的 parent 和其他来源 |

```yaml
tracking:
  status: pending
```

```yaml
tracking:
  status: none
```

```yaml
tracking:
  status: configured
  sources:
    - repository: antdv-next/antdv-next
    - repository: ant-design/ant-design
```

`parent` 来自关系观察，`tracking` 来自用户选择，两者互不自动赋值。
来源不能是管理主体，不能重复；可以选 parent、其他仓库或两者，
不要求用户穷尽回答所有可能来源才保存一个明确选择。

新增、替换或移除来源都对应用户明确的变更意图。
移除最后一项需要明确停止最后一项追踪的决定，不能靠空数组猜测 `none`。
移除来源不删除其已有历史；一次临时查看别的仓库不自动加入持续追踪。
多来源只表示配置可以保存多个选择，不自动巡检、同步、并发调用或启动 Agent。

## 8. 跨字段组合与限制

生命周期、关系状态、工作 fork 绑定和追踪意图分别判断，不因某一组状态
自动改写另一组。各组只能采用以上合法形状，再满足以下跨字段约束。

| 规则 | 要求 | 备注 |
| --- | --- | --- |
| 主体一致 | 工具 `repo`、根 `repository`、本地项目目录身份一致 | 普通操作不自动改成 parent 或反向归属的项目 |
| 直接来源 | `parent.repository != repository` | 比较前使用统一规范化规则 |
| 工作 fork | 非空 `working_fork != repository` | 同仓库分支开发不需要伪装成工作 fork |
| 追踪来源 | 每个来源不同于主体，且集合不重复 | parent 与某个 tracking 来源相同是允许的 |
| 关系与意图区别 | `parent.none` 不推出 `tracking.none` | 非 fork 也能追踪其他仓库 |
| 关系与贡献区别 | `parent.confirmed` 不要求绑定工作 fork | 直接管理自己的 fork 时常用 `working_fork: null` |
| 归档与其他配置 | 归档不清空 parent、绑定或追踪选择 | 配置保留不等于获准执行维护任务 |
| 版本与结构 | 拒绝未知版本、未知键和非法状态组合 | 不从旧格式或缺失字段猜测转换 |

已查明且已选择追踪意图的六类关系组合如下；`unknown` 和 `pending`
另按各自状态保留，不强行归入已确认类别。

| 主体 | 追踪选择 | 字段组合 | 备注 |
| --- | --- | --- | --- |
| 非 fork | 不追踪 | `parent.none` + `tracking.none` | 关系事实和用户选择分别获得 |
| 非 fork | 其他仓库 | `parent.none` + `tracking.configured` | 不需要 parent 才能追踪 |
| fork | 不追踪 | `parent.confirmed` + `tracking.none` | 有 parent 不等于持续追踪 |
| fork | 仅 parent | `parent.confirmed` + 来源 `[P]` | P 是已明确选择的 parent |
| fork | 仅其他仓库 | `parent.confirmed` + 来源 `[X]` | 不自动补入 P |
| fork | parent 与其他仓库 | `parent.confirmed` + 来源 `[P, X]` | 不是自动执行所有来源 |

## 9. 初始化与后续更新

在用户明确初始化主体、尚未查明关系也未选择追踪时，最小完整候选为：

```yaml
schema_version: 2
repository: darkingtail/antdv-next
lifecycle:
  status: active
parent:
  status: unknown
contribution:
  working_fork: null
tracking:
  status: pending
```

若初始化时已成功核实关系，可使用对应 `none` 或 `confirmed` 形状和真实时间，
不能为了例子完整而编造来源或时间。已有合法配置不按这个示例重置，
尤其不能清空用户的追踪选择、工作 fork 或恢复归档项目。

普通 `repo_config` 查看缺失配置时返回未初始化，不自动创建。
`init` 不隐式生成知识库、建立 Todo、启动巡检或 Agent。
字段缺省只在明确初始化时构造，不在读取旧文件时自动补值。
配置修改沿用短锁、旧快照 digest 比较与原子写入方案；这些是接口和存储约束，
不增加 YAML 的业务 revision。冲突不能自动覆盖用户未看过的新内容。

代价是字段名较长。泛指观察的 `observed_at` 和泛指检查的 `checked_at`
不够直接，不能只靠注释弥补用户已指出的歧义。

该候选仍适用于成功确认“没有 parent”的 `none` 状态；
不是只有确认存在 parent 才能记录。失败不更新成功时间，未知不带时间，
只读查看不写配置等规则保持不变。代码同步时间继续属于具体操作记录，
本轮不新增任何同步配置字段。

**仅提出替代命名，等待用户确认。** 本文现有字段和全部 YAML 示例仍为
`observed_at`，没有改业务代码、真实配置、活动数据或任务状态。

## 13. 最近一次代码同步时间（配置外的候选）

用户询问是否也应记录“什么时候同步过代码”。本轮主助手静态读取发现，
现有 `sync_fork` 入口没有保存成功同步时间；现有 `sync_history` 读取的是
版本对齐报告，而非 fork 分支同步流水。日常追踪的 `last_checked`
同样不能充当代码同步时间。没有执行远端同步或运行产品验证。

本轮已续接 Claude 讨论，主助手建议记录这项信息，但**不增加
`parent` 下的时间字段，也不新增 config 顶层域**。
候选查询属性为 `last_successful_sync_at`，来自具体方向的成功同步记录；
当前入口缺少流水的事实是后续实施缺口，不假装本轮已补齐。

| 范围 | 候选规则 | 备注 |
| --- | --- | --- |
| 身份 | 源仓库/分支 → 目标仓库/分支，并区分远端和本地 | main 的成功不能代表其他分支，远端成功不能代表本地已拉取 |
| 时间 | 最近一次已确认成功的同步操作完成时间 | 不用开始时间、检查时间或失败尝试的结束时间 |
| 无需改动 | 成功执行但已无需变更也可形成成功记录 | 显示其无变更结果，不能声称刚写入了新提交 |
| 后续失败或结果未查明 | 不覆盖旧成功时间；最新尝试结果单独可见 | 防止只展示旧成功掩盖新问题 |
| 没有记录 | 显示无记录 | 不等于从未同步，不能补造其他工具执行的时间 |
| 当前是否对齐 | 另行核实当前分支差异 | 源仓库后续可能变化，成功时间不是持续对齐证明 |
| 保存方式 | 从同步流水派生查询值，避免 config 与流水双份权威 | 存放位置候选见下文；完整流水格式仍待设计 |

这项提议与 `parent.relation_verified_at` 的命名候选各自待确认；
用户询问需要性不等于批准新增字段、自动同步或实施。

### 13.1 存放位置候选（文件名已按用户要求修正）

用户随后要求文件名以 `parent` 开头，经 Claude 聚焦复核无关键冲突，
将此前主助手提出的 `fork-sync.yaml` 候选改为：

`parent-sync.yaml` 拟保存每次相关同步的源、目标、分支、范围、结果和时间等事实，

无记录与文件读取失败应区别报告，不能都显示成“未同步”。

此次命名纠正只更新文档，没有创建或重命名活动文件、改动原报告、
执行同步或确定完整记录格式；`sync_fork` 工具与 Skill 名称均未改变。
