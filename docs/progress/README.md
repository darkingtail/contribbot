## 记录约定

发生实质进展、验证结果、阻塞变化或用户决定时及时落盘。
每日检查没有发现可核实的新进展时，简短记录这一事实与尚待处理的下一步，
不为了写日报重复测试、重复派工或制造任务。
无法读取某个任务、工具或运行环境时注明不可核实，不能据此判断没有进展。
漏跑日期不自动补造记录；确需回顾时标明回顾时间和原始证据日期。

每份记录包含：

| 内容 | 要求 | 备注 |
| --- | --- | --- |
| 总体判断 | 一句话说明正在做什么、处在哪个环节 | 不用没有依据的完成百分比 |
| 三段现状 | 前面发现任务、中间执行任务、后面交付与沉淀 | 区分已设计、已实现、已验证和未完成 |
| 当日进展 | 代码、设计决定、验证与排障的真实变化 | 未采纳的建议不能写成确定方案 |
| 证据与限制 | 测试结果、候选范围、记录入口、未覆盖内容 | 历史测试与本日重跑分别说明 |
| 阻塞与待决 | 已确认问题、未知原因、需要用户决定的事 | 提问先解释场景和影响 |
| 下一步 | 少量按顺序可执行的动作 | 不由日报扩大工作授权 |
| 工作区与数据 | 分支、是否已提交、开发态连接和重要数据操作 | 不写凭据，不把配置正确当成业务通过 |

新一天从实际代码、最新结果和真实用户决定恢复上下文，不能只复制上一天日报。
旧看板或设计文档与实现有差异时，应标明差异及依据；不能将过期 Next 当作
新阻塞，也不能只因文档说完成就跳过核查。

## 边界

只更新日报不意味着用户同意结束 Todo。完成、取消、归档、提交推送和 GitHub
写入分别遵循既有授权。自动记录不运行新业务测试、不启动巡检、不清空数据、
不改 Codex 配置，也不替用户确认计划或人工验收。

进度文件不包含 API key、token、原始鉴权配置或无关私密内容。
固定时刻的自动记录是辅助；当天工作中的助手仍应及时更新本日记录。
